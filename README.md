# Atherloom Escape · 文字密室与跑团

一套让人类与 AI 以玩家或观战者身份共同参与的跨平台文字密室与跑团剧场。

## 当前目标

- 独立网页版 / PWA 是游戏本体，提供密室逃脱与跑团剧场两类玩法。
- Atherloom 是拥有本地人格、记忆与共同日记能力的完整入口。
- Codex、Kelivo、RikkaHub 通过 MCP 接入。
- AstrBot 通过专用插件接入并负责后台唤醒人格。
- Relay 保存唯一真实状态；模型不能看到未发现答案，也不能用自然语言绕过裁判。
- 裁判 / GM 使用独立人格、独立模型路线与独立会话，不占玩家席，也不与游玩人格共享私有上下文。

## 随机组合

建局时分别抽取一项世界观与一项故事气质，并把随机种子写入存档：

- 世界观：古代、现代、科幻、近现代、中世纪、西幻。
- 故事气质：甜宠、日常、正剧、BE、恐怖。

同一局在任何设备恢复时都得到完全相同的组合。

## 玩法与席位

协议允许 1–4 个席位。身份类型为 `human` 或 `ai`，席位角色为 `player` 或 `spectator`：

- 玩家席拥有行动轮次，可以观察、操作或进行跑团 d20 检定。
- 观战席不占行动轮次，不接收私有线索，但可以使用公共聊天频道。
- 预设模式包括 AI 独行、双人协作、AI 小队、混合小队、人类解谜 / AI 观战、AI 解谜 / 人类观战。
- 跑团与密室共用世界和气质抽选；跑团另有角色卡、任务、状态和服务端骰点。

## 裁判隔离

裁判不是一种玩家席。房间只保存公开的裁判人格名和路线标签；模型 API Key、裁判令牌和人格私有提示不写入房间状态。正式接入时，即使裁判与玩家使用同一家模型服务，也必须使用两个独立会话。当前网页中的“本机规则演示”是确定性演示，不冒充真实 AI。

## 成人内容边界

游戏仅向成年人开放，应用层不额外设置 NSFW 关键词屏蔽。成年人之间自愿的私人剧情由所选模型与服务线路处理；未成年人仍被禁止进入，模型提供商自身不可绕过的规则仍然有效。玩家或人格保留拒绝不愿参与内容的权利。

## 目录

- `shared/`：平台无关的随机、事件与状态规则。
- `worker/`：Cloudflare Worker / D1 Relay。
- `web/`：独立 PWA。
- `mcp/`：Codex、Kelivo、RikkaHub 共用 MCP 桥。
- `adapters/`：Atherloom 与 AstrBot 适配说明及代码。
- `tests/`：协议与状态机测试。

跨平台能力与尚需真机确认的边界见 [`docs/platform-compatibility.md`](docs/platform-compatibility.md)。

## 本地验证

```powershell
npm.cmd run check
npm.cmd run dev
```

本地预览默认在 `http://127.0.0.1:8794`。本地演示数据保存在浏览器 `localStorage`，正式联机数据以 Relay 为准。

## 发布边界

- 推荐把开发仓库设为私有，通过 GitHub Pages 公开游戏页面。
- 若账户方案不支持私有仓库 Pages，则开发源码保持私有，另用公开部署仓库只保存自动生成的网页产物。
- GitHub Pages 和浏览器包不得包含 Relay 身份令牌、MCP 令牌、模型 API Key、未公开谜底或服务端裁判逻辑。
